# BuildPlan — implementation entry point

Read the current OWNER brief, `APP_SPEC.md`, `AGENT_PROTOCOL.md` and the current
summary at the top of `PROJECT_STATUS.md`. For analyzer work also read
`docs/ANALYZER_CONTRACT.md`. Read older reports only for the affected decision.

The latest explicit OWNER instruction determines the authorized outcome and
scope. Historical NEXT lists, research verdicts and foundation-stage exclusions
are not additional active orders. Record and resolve an affected conflict;
do not ask the OWNER to reauthorize routine work already within the brief.

Keep these boundaries:

- Accepted semantic model → commands/compiler → viewers. No separate UI mesh truth.
- Preserve source observations, per-property meaning/provenance, uncertainty and
  the distinction between source, accepted decision and applied geometry.
- Runtime never reads benchmark answers. No house-identity exceptions.
- Stable semantic IDs survive regeneration; triangle indices and diagnostic prose
  are not domain identifiers or flags.
- OCR/detectors/ensembles and inference order are replaceable on evidence.
  Own code has no permanent priority over a better measured alternative.
- Use current types and seams. Add a new service, DSL or kernel only for a
  demonstrated need. ForgeShape is read-only under the present authorization.
- Keys stay outside source/APK/logs. Remote data and paid calls stay within the
  authorized project scope and budget; offline analysis remains useful.

Workflow, checks, delivery and session continuation are specified once in
`AGENT_PROTOCOL.md`. A build, a diagnosis or a checkpoint is not product acceptance.
