# Council A — Source / Evidence Architect (005A post-review)

## 1. Strongest improvement

**The page is named by what it is, and the content hash no longer contains the page.** `logicalSourceUrl` (`packages/source-package/src/logical-url.ts:136-139`) uses the page's same-site canonical link, or else the fetched address with attribution families removed, the remaining parameters sorted, and the fragment and trailing slash folded. `acquire.ts:78,181-184` builds `id`/`canonicalUrl` from it, and `hash.ts:51` hashes only `{project, adapter}` as identity **[C]**. The clean and tracked Kosaćce links now seal one id (`src-mf6628752fa61f-56408a0bd9`) and one content hash (`9cb4f520…`), even though their page hashes differ (`4c6c7924…` / `0ea89bb0…`), per `identity/kosacce-clean-vs-tracked.json` **[M]**. The fix is a structural rule, not two special-cased keys, and it fails in the safe direction: unknown keys stay (`logical-url.ts:24-26`) **[C]**. The supporting fixes also hold up. The redirect target is kept in a cache sidecar (`cache.ts:32,38`; `acquire.ts:397`). Only transient failures are retried (`net.ts:365`; `acquire.ts:411`). A cancel is `ABORTED`, not `TIMEOUT` (`net.ts:328`). The idle deadline is re-armed on every body chunk (`net.ts:338,380`) **[C]**.

## 2. Largest remaining genericity risk

**An unlabelled plan is read as a ground-floor plan.** `planStoreyOf` (`packages/reconstruction/src/layout.ts:70`) maps storey `UNKNOWN` to `GROUND`. By design, the ARCHON adapter gives `UNKNOWN` for every floor-fragment index except 1 and 3 (`adapters/archon.ts:168-171`). Its high-resolution originals carry no descriptive slug (`archon.ts:150-151`), so that index is their only storey evidence **[C]**. The adapter's "no claim rather than a guess" becomes a guess one layer later.

The resolver picks the base storey's copies by `planStoreyOf` and sorts them dimensioned first, then by pixels (`plan-resolution.ts:445-455`). An unlabelled upper plan therefore joins the ground copies and may be tried first. `CROSS_COPY` (`plan-resolution.ts:332`, width and depth within 5 %) would then count the real ground plan, which has the same outer walls, as corroboration for it **[C mechanism, I outcome]**. A related gap in the adapter: a room table whose heading is not `parter|przyziemie|poddasze|pietro` (for example a basement) is skipped without recording a failure (`archon.ts:297-298`), so no warning can report it **[C]**.

The evidence for this mapping is thin. Three of the four ARCHON development packages have only GROUND plans, and Marcówki has GROUND+ATTIC. None has an UNKNOWN-storey plan, a basement or a "piętro" (`before/*/source-package.json`) **[M]**. The 1→GROUND, 3→ATTIC mapping comes from one two-storey house. **No gate catches this.** `archon.test.ts:123` only checks the adapter half (index 2 → UNKNOWN), and the shape-family fixtures set roles directly with no adapter (`reconstruction/test/pipeline.ts:58`) **[C]**.

## 3. Possible hidden overfit

- **The guess rule ignores the failure code.** `warnings.ts:63` marks every failure on a `VARIANT_CONVENTION` address as INFO ("the published copy was used"), whatever the code. Its only test uses a 404 (`warnings.test.ts:10`), which matches the development set: 7–9 guess 404s per ARCHON package (`before/*/source-package.json`) **[C][M]**. If a larger original exists but times out or returns 503 twice, the pixels the OCR legibility gate needs are lost, and the run reports this as information **[I]**. How to detect: inject 503×2 on a guess that exists and expect LIMITING.
- **Merge/split.**
  - *Attribution families* (`logical-url.ts:40-69`): these merge two houses only if a publisher selects content with `utm_*`, `mc_*`, `pk_*`, `ga_*`, `_hs*` or `*clid`, which is implausible. Unknown keys split, which is the declared safe side **[I]**.
  - *Canonical rule — the weaker one:* any same-domain https canonical is believed, including the site root, a listing page, or a parent product declared by a variant page (`logical-url.ts:114-129`). For a page with no publisher id, `identity.ts:35-36` names the model `u`+sha256(canonical). On the phone that modelId keys the persistent progress file (`ConstructionProgress.kt:44-45`, `ProgressStore.kt:103-107`). Two houses behind one template canonical would share one construction record **[C]**. Tests cover only honest self-canonicals and foreign hosts (`logical-identity.test.ts:122-141`). ARCHON is immune, because its code is read from the fetched URL (`archon.ts:318-320`).
  - *Provenance:* the `basis` that decided the name is computed (`logical-url.ts:133-139`) but never persisted **[C]**.
- **The "evidence-only" hash still contains addresses.** Variant URLs and failure targets are still hashed (`hash.ts:45,56`), so a signed or cache-busted CDN would bring the per-fetch nonce back **[I]**. A live 404 (`HTTP_STATUS`) replays as `OFFLINE_CACHE_MISS` (`acquire.ts:402`), so live and replay hashes differ whenever a guess 404s. The committed identity proof compares offline with offline (7 misses on each side) **[C][M]**.
