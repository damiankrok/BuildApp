Consequences beyond the two ARCHON URLs:

- **Generic adapter without a publisher id** (`generic/index.ts:57-69` finds a JSON-LD `sku`/`productID`/`mpn` or a ≥10-hex path segment; otherwise `undefined`): `identity.ts:36` derives `slug = 'u' + sha256(canonicalUrl)` → **modelId, label and therefore the model hash change with `gclid`**, trailing slash, or query order. That is the case that "special-casing two query keys" would not fix.
- **Cache replay ≠ live** after any redirect: `acquire.ts:361` hands back the *requested* URL on a cache hit while `:369` hands back the *final* URL live, so an offline replay of a redirected page produces a different `canonicalUrl`, `id` and `contentHash` than the live run it replays. The offline test (`acquire.test.ts:274-300`) never redirects, so this is untested.
- **Fetch/discovery order can change a package** for one URL exposed by two documents with different captions: `acquire.ts:204-205` keeps the *first* candidate at equal trust (strict `>`), the sort keys at `:119` omit `exposedBy`, V8's stable sort keeps input order, and the caption chosen at `:313` enters the asset id (`:315`) and the content hash (`hash.ts:33`). Deterministic for a fixed page, but a function of document enumeration order, not of content.
- `contentHash` cannot say "same published material": it hashes `pageHash`, which changes on every fetch of this publisher (verified: same 31 assets, same facts/rooms/specs, different `pageHash` today vs 004A). The hash the module's header promises (`hash.ts:3-7`) is in practice a per-fetch nonce.

**Which production function should own a tracking-invariant LOGICAL identity, without special-casing query keys:** one pure function in `source-package` (call it `logicalSourceIdentity(pkg | draft)`), used by `acquire.ts:170-171` for `pkg.id`/`pkg.canonicalUrl` and by `identity.ts:34-40` for the slug, with this precedence:
1. the adapter's `project.externalId` (the publisher's own project code — `archon.ts:318-323`, `generic/index.ts:57-69`), when present;
2. else the page's own `<link rel=canonical>` / `og:url` — already parsed at `generic/markup.ts:148` — accepted only when it passes `validatePublicSourceUrlSecurity` and shares the registrable domain (`generic/assets.ts:51-59`) with the fetched page, so a hostile page cannot claim another site's identity;
3. else the final post-redirect URL normalised by structure, not by key list: scheme+host lowercased, default port dropped, fragment dropped, **query dropped entirely**, trailing slash folded. Dropping the whole query is safe precisely because identity is not what is fetched: the request still uses the URL as given (the CDN test at `archon.test.ts:169` stays valid for asset URLs), only the *name* of the result changes. A page whose project genuinely lives in a query parameter (`?id=123`) is covered by (1)/(2) via its publisher id or canonical link.

**Which hashes must be evidence-only:** `sourcePackageContentHash` should hash `{schema, version, project.externalId/publisher, adapter}` + assets + facts + specs + rooms + failures (`hash.ts:44-48` already unordered) and **exclude** `canonicalUrl` and `pageHash`; both stay in the package (with `requestedUrl`, already in the schema) as provenance. `pkg.id` should be `stableId('src', logicalSlug, { contentHash })` or the logical identity alone. Then `observationGraphHash`, `metricEvidenceHash` and `candidateHash` become invariant for free, because they consume only `pkg.id` and `pkg.contentHash`. `specifications.ts:110` should stop using `pageHash` as the specification's `variantByteHash` and hash the specification text it actually read.

## 5. Hard vs soft

Must stay **hard**: `validatePublicSourceUrlSecurity`, `assertFetchable`, redirect re-validation, byte cap, media-type check (security); decoded-size truth over declared size (`acquire.ts:143-147`); `decodeImage` size cross-check; `analyze.ts:135` size mismatch; schema validation of the sealed package; the phone shim's *refusal* of unknown characters (approximating ICU would be worse than refusing).

Should become **scores / late validation / named partial**: `HTTP_STATUS` on a guess (evidence, not failure — already treated so in prose, but not in counts); `DIFFERENT_CROP` tolerance 0.02 (a score on the asset, not a split decision); `CHANNEL_TRUST` numbers and the 0.92/0.85/0.8/0.6/0.55 role confidences (fine as scores; must never be compared for equality across adapters); "no plan and no elevation → NO_DRAWINGS" is right; **new**: "exposed DIMENSIONED plan discovered but not fetched" must be a named `SOURCE_LIMITED` partial *before* any geometry gate runs — the geometry gates (`FOOTPRINT_AREA_WRONG` etc.) must not be reachable on an incomplete source without saying so.

## 7. Top 5 findings

1. **HIGH — Identity and evidence are conflated in the package hash and id.** `hash.ts:43` hashes `canonicalUrl` and `pageHash`; `acquire.ts:170` seeds `pkg.id` with the URL spelling; `identity.ts:36` names a generic project by `sha256(canonicalUrl)`. Result (verified live): the same 31 assets/9 facts/14 rooms/8 specs get two package ids, two content hashes, two graph/metric/candidate hashes for `?gclid=…`, and would get two *models* on any publisher without an id in the path. `contentHash` also changes on every fetch of the same page. **Smallest generic change:** a `logicalSourceIdentity` with the precedence in §1.1 (publisher id → canonical link on the same registrable domain → structurally normalised URL with the query dropped), `contentHash` over evidence only, `pageHash`/`canonicalUrl`/`requestedUrl` kept as provenance; `specifications.ts:110` hashes the text it read.

2. **HIGH — One transient fetch failure on an exposed plan copy becomes a geometry verdict.** `acquire.ts:134-135` and `archon.ts:368` drop a failed candidate after a single attempt (`net.ts` has no retry, and its 20 s timer does not cover the body); the claims of the failed candidate are never computed (`acquire.ts:200-203` runs only over `measured`); `run.ts:202-219` gates only on "no plan and no elevation"; `layout.ts:195` then reads whatever plan frame is left. On the phone this yields `planFrames 1` → `FOOTPRINT_AREA_WRONG 33.15 m²` where the desktop says ACCEPTED, and the failure screen (`FailureDetails.kt`) shows nothing about the source. **Smallest generic change:** retry-once on transient codes in `fetchBytes`; `channel` (+ role claims) on `AcquisitionFailure`; a `SOURCE_LIMITED` stop in CLASSIFYING_SOURCES when an exposed FLOOR_PLAN candidate was not fetched and only an `AREA_TABLE`/`UNKNOWN` copy remains; `sourceSummaryOf` counts into `failure.diagnostics`.

3. **MEDIUM — Drawings can vanish *after* acquisition with no failure recorded.** `analyze.ts:117-128` turns a null cache read (partial `.bin`/`.type` write, `cache.ts:28`) or *any* decode exception (including allocation errors at a 1.2–1.5 GB phone peak) into a skipped asset and an unresolved gap; `run.ts:259-268` decodes every asset a second time and retains all rasters. `planFrames` drops silently. **Smallest generic change:** count skipped drawings by cause in the trace and in every failure's diagnostics; classify allocation errors as `RUNTIME_MEMORY`; decode once and share the prepared raster with `rasterCache`.

4. **MEDIUM — Ordering is not content-total, and free text is sorted with `localeCompare`.** `acquire.ts:204-205,313` choose a caption by input order at equal trust (`exposedBy` is in no sort key; `dedupe` keeps one record per document), so the asset id and the content hash depend on document enumeration order; `roles.ts:60` and `archon.ts:266` (and `source-metrics/parse.ts:177`, `callouts.ts:833` downstream) order free text with `localeCompare`, which on the phone refuses `…`, `„”`, `’`, `ß`, `½` on a tie (`text-tables.ts` bases 303/marks 94) and fails the whole run only there. **Smallest generic change:** `compareCodeUnits` (`text.ts:56`) for every ordering inside `source-package`; a total sort key including `exposedBy`; caption chosen by content (sorted caption set), asset id from byte hashes + roles.

5. **MEDIUM — Replay and live disagree, and a body read never times out.** `acquire.ts:361` returns the requested URL on a cache hit while `:369` returns the final URL live, so an offline replay of any redirected page has a different `canonicalUrl`/`id`/`contentHash` than the run it replays; `net.ts:297` clears the timeout before `readCapped` (`:317`), so a stalled body on a mobile link hangs the ACQUIRING_SOURCE stage indefinitely with no event. **Smallest generic change:** store the final URL (and status) in the cache sidecar and return it on a hit; keep the timer alive across the body read.

**Falsification.** The claim "the analyzer is becoming generic" is falsified by any of: (i) the same publisher page reached through two spellings of its address, or through two networks, ending in different *classes* of outcome (ACCEPTED vs a geometry gate code) without the run naming a source difference; (ii) a package whose `contentHash` changes with no change in assets, facts, rooms or specifications; (iii) a package whose `canonicalJson` changes when the page's `<img>`/`srcset`/link order is permuted; (iv) a project that completes on the desktop and fails on the phone with `TEXT_NOT_SUPPORTED_ON_DEVICE` because of an ellipsis in an alt text. Tests T1–T7 in §1.3 make each of these a red line rather than a phone report.
