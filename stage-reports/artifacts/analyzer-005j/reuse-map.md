## Admission rules every reused piece must keep

These are BuildPlan's evidence architecture, not preferences:

1. **Observations, not decisions.** A reused piece emits observations into the graph (`source-observations/src/schema.ts:54` `ObservationKindSchema`, `:279` `RelationKindSchema`), or a post-seal metric. It never adds a step to the deterministic resolver (`reconstruction/src/plan-resolution.ts:530` `resolvePlan`).
2. **Non-circular metric.** Scale never creates, chooses or promotes a reading (`source-metrics/src/metric-solution.ts`). Nothing reused may infer geometry from the scale it is supposed to witness.
3. **The published figure may veto, never select** (`plan-resolution.ts:956–1082`). Nothing reused reads a published area to pick between candidates.
4. **Provenance and determinism.** Every observation carries its provider and version. A production piece must give bit-identical output on Node 18 and 22 and on x86-64 and arm64 V8, which is the 005G/005H bar.
5. **Licences**
   - **COPY/ADAPT** only from MIT, Apache-2.0 or BSD sources, with their notice shipped in `assets/licenses/`.
   - **GPL/AGPL code is never copied** into the closed app: Raster-to-Graph, DeepFloorplan, HEAT, Ultralytics.
   - Code that is **non-commercial or source-available** (CubiCasa5K repository, SymPoint, ArchCAD, CAGE's Commons Clause, NVIDIA SegFormer) is **REIMPLEMENT_FROM_PAPER** at most, written without looking at that code.

**Classification legend**

| class | meaning |

| COPY/ADAPT | port permissive code with its notice |
| REIMPLEMENT_FROM_PAPER | write from the published description |
| RESEARCH_ORACLE_ONLY | run only in `research/` as a comparison |
| REJECT | do not use |

## Draft priorities

**Why evaluation and interpretation come first.** 005I's own conclusion was that the documented boundary failures are *interpretation*, not missing perception. External line providers added 0.00 m of ink-supported exterior wall on all 7 real houses (`STAGE_BUILDPLAN_ANALYZER_005I_…md` §L).

Ordered by value for the least risk to resolver semantics.

1. **Evaluation layer, reimplemented from fpvec and RoomFormer:**
   - tolerance-based wall F1 (row 14), with Hungarian matching (row 25);
   - edit cost (row 12);
   - r_val with double walls (row 19);
   - room IoU, corner and angle (row 26).

   This is post-seal and research-first. It changes no production hash, and it gives the coordinator a wall-level, effort-weighted view that `evaluateCandidate` lacks.
2. **Typed room graph (rows 8 and 10).** Port ResPlan's contact-length and via_opening logic (MIT, with notice), minus its fallback edges. Start as an Evidence-Pack diagnostic; make it an observation only after an additive relation kind.
3. **Junction inventory and junction-degree audit (rows 3 and 18).** Built from BuildPlan's own bands; observation and audit only.
4. **Deterministic texture/periodicity witness (row 24).** Aimed at the 005I blind-8 BOUNDARY failure class.
5. **Bake-off protocol rules (rows 15 and 16).** An ink-gate admission rule and the "purity > F1_base / 2" acceptance test for any future external provider.

**Explicitly not recommended:** replacing any of `runLengthBands`, `solidLayer` / `classifyGap` / `solveOutline` / `completeBoundary`, `planWallTopology`, `readInterior` or `fuseCandidates` with an external implementation. Each external analogue is cruder, and the BuildPlan versions carry the recorded-decision semantics the evidence architecture depends on.
