### F2-6 (P2, F-8 remainder): Three scope gaps remain in the guard

**Evidence** (`tests/architecture/research-isolation.test.ts`)
1. `filesUnder()` (line 35) skips every directory named `third_party`. The new native-code check
   (`filesUnder('apps/android', /\.(c|cc|cpp|h|hpp)$|^CMakeLists\.txt$/)`) therefore would not scan a llama.cpp vendored
   at `apps/android/app/src/main/cpp/third_party/llama.cpp/`, the usual place for one. Only the parent `CMakeLists.txt`
   naming it would be caught, and a neutral directory name evades that too. The `.so` and assets checks share the skip.
2. `apps/*/tools/**` is still not scanned. Eight tracked files live in `apps/android/tools/`, including
   `fetch-nodejs-mobile.mjs`, which is the existing pattern for fetching a native runtime at build time.
3. The npm manifest check (`:90`) still matches only `research|bakeoff|pytorch|torch|opencv|python|deeplsd|elsed|sam`.
   A production `apps/web` dependency on `@huggingface/transformers`, `@mlc-ai/web-llm` or `@wllama/wllama` passes, and
   so does `onnxruntime-web` pointed at a VLM.
4. Minor: base64 split into lines under 256 characters (e.g. MIME 76-character lines, or a JSON array of 200-character
   strings) evades the 256-run check (probed). The 2 MiB cap bounds it. Only deliberate obfuscation reaches this, so it
   gets no separate finding.

**Fix.**
- Run the native, `.so` and assets scans over `git ls-files` rather than a walk that skips `third_party`.
- Add `apps/*/tools/**` to the HARNESS and `VLM_RUNTIME` scans.
- Extend the manifest regex with `transformers|web-llm|wllama|llama|ggml|mlc|mediapipe|genai`.
