# N9-00 — root-cause matrix of the N7/N8 defect classes

## Columns and sources

Each row runs: source observation → FIRST_BAD (file/function, stage) → information lost → false geometry → the gate that let it through and why → systemic correction → house-independent test.

Where each kind of statement comes from:
- **FIRST_BAD and false geometry:** the stage reports (REPORT_ONLY, **RO**), each traced in its own stage on the code of that time.
- **Why the gate passed:** checked against today's code (CODE_VERIFIED, **CV**), with references to `validation-gap-matrix.md`.
- **"Systemic correction":** what would have caught the class *without* knowing the house. It is the proposal of this audit (HYPOTHESIS until built and measured), not what the N8 stage did. What N8 did is in the "fix made" column.

## The common shape (CV for the gate column, RO for the FIRST_BAD column)

Every class above has the same two properties:
1. **FIRST_BAD is in the reading** (plan decomposition, registration, door assembly, void reading, roof emission), never in the model or the compiler.
2. **No check compares the result with the source in a way that can fail the run.** The checks that do compare (`verifyAgainstViews`, `alignFacades`, `crossViewResiduals`, `viewAudit.lost`) exist and often *see* the problem, but their outputs are not inputs of `modelCompleteness`. The ones that are inputs (`bodyCompleteness`, the layout gate, model refusals) compare the model with the analyzer's own reading, or with the model itself.

So each N8 stage found its defect by eye on the ARCHON board. The pipeline itself could not have found any of them.
