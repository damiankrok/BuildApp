# N9-00 — schema 1.7.0, candidates, Android and the analyzer contract (read-only audit)

Base `0d03d60`. Nothing was changed or refreshed.

Probes:
- `research/analyzer-n9-00/schema-probe.ts`: loads, migrates, reloads and compiles every fixture, the 8 N8-03D1 models and the sealed candidates.
- `research/analyzer-n9-00/contract-diff.ts`: compares the committed Android contract fixtures with what the API answers today, by shape and by value.

Both only read.

## 1. MODEL_SCHEMA_COMPATIBILITY — risk: LOW

**Code** (CV):
- `packages/model/src/schema.ts`: `MODEL_SCHEMA_VERSION = '1.7.0'`; `SUPPORTED` adds 1.7.0; `RoomSchema.holes` is optional.
- `migrate.ts`: step 1.6.0 → 1.7.0, `newCollections: []`. `newField` refuses a 1.6.0 file carrying `rooms[i].holes` as mislabelled.
- `validate.ts`: `ROOM_HOLE_OUTSIDE` / `ROOM_HOLES_OVERLAP`.
- `commands.ts`/`apply.ts`: `createRoom.holes`.
- `geometry/src/features.ts` `compileRoomFloor`: `extrudePlanRegion` with holes.

**Replay** (RV), `schema-probe.ts`:

| input | stated | loads as | migration steps | other issues | reload idempotent | compile errors |
|---|---|---|---|---|---|---|
| `demo-house-1.0.0` … `-1.7.0` (8 files) | 1.0.0–1.7.0 | 1.7.0 | 7 → 0 | none | yes (8/8) | 0 (2332 triangles each) |
| `marcowki-ge-1.2.0` … `-1.7.0` (6 files) | 1.2.0–1.7.0 | 1.7.0 | 5 → 0 | none | yes (6/6) | 0 |
| 8 N8-03D1 regression models | 1.6.0 | 1.7.0 | 1 | none | yes (8/8) | 0 |

- **Idempotence:** serialising a migrated model and loading it again gives no further migration and the same bytes, in every case.
- **Old readers:** a reader on schema ≤ 1.6.0 refuses a 1.7.0 file by name (`UNSUPPORTED_SCHEMA_VERSION`). It does not misread it. CV for the current code; observed once in N8-03D2, where a stale web bundle could not load the 1.7.0 models (RO, N8-03D2 session).
- **Remaining risk:** any deployed client (web or editor build) older than `0d03d60` cannot open models saved since. This is by design; it is not a defect.

## 3. MOBILE_SCENE_CONTRACT — risk: LOW

**Code** (CV):

- `apps/android/app/src/main/java/com/buildplan/preview/scene/BundleParser.kt:27,48` checks only the bundle version. `Json { ignoreUnknownKeys = true }` (`:29`).
- `modelSchemaVersion` (`Bundle.kt:37,188`) is displayed in `HouseSheets.kt:249` and never compared.
- Room holes arrive as triangles: the `ROOM_FLOOR` part is unchanged (`ModelScene.kt:74,191`).
- `apps/android/app/src/main/assets/scenes/*`: regenerated by `mobile:export-scenes` in N8-03D2. Only `contentHash`, `generatedFrom.modelContentHash` and `modelSchemaVersion` changed. Mesh, triangle and object counts are equal for every scene (RO, N8-03D2 diff of `index.json`).

Not verified: the Kotlin unit tests and the APK were not run. That needs Gradle and an emulator and is outside this audit. No claim is made that the APK is broken or that it works.

## 4. ANALYZER_API_CONTRACT — risk: MEDIUM (stale contract evidence, not a broken contract)

**Failing test:** `apps/analyzer-api/test/android-contract.test.ts`, *"match the real responses of the API, byte for byte after normalising the job id and the clock"*.
- It regenerates every response with `captureAndroidContract()` and compares each one byte for byte with `apps/android/app/src/test/resources/analyzer-contract/<name>`.

**Per file** (`contract-diff.ts`, RV):

| file | state | what differs |
|---|---|---|
| `submitted.json`, `status-running.json`, `refusal-unsupported-publisher.json`, `not-found.json` | **identical** | — |
| `status-completed.json` | 7 leaves | `candidateHash`, `modelHash`, `sceneSha256`, `sceneContentHash`, `sceneBytes` 101719 → 121022, `quality.L1` 12 → 18, `unresolved` 6 → 7. **Shape identical.** |
| `result.json` | 15 changed leaves, **52 paths only in the fresh answer, 0 paths only in the committed one** | `analyzer.solver` **2.3.0 → 2.17.0**, `analyzer.service` 1.1.0 → 1.2.0, `metricEvidenceHash`, hashes, `counts.commands` 53 → 63, meshes 46 → 50, triangles 916 → 1132. New members: `preview.outcome`, `preview.built.*`, `preview.provisional`, `preview.partial`, `preview.completeness.*`, `quality.byFamily.INTERIOR_DOOR`. |
| `scene.json` | values | Every path exists in both. Differences are values and array lengths: the synthetic job's model is a different building after 14 solver versions (e.g. object 0 was a wall, now a door). `generatedFrom.modelSchemaVersion` 1.6.0 → 1.7.0. **Shape identical.** |
| `meta.json` | 1 leaf | `sceneSha256Header` |

**When it went stale.** The committed `result.json` was captured at `79e9bbc` (005L, 2026-10-07) and records `analyzer.solver = 2.3.0`. The response embeds the solver version, so the first solver bump made the test fail:
- `f6d1532`, solver 2.4.0, 2026-10-22 (CV: the field is in the response; git history of the fixture).
- Every stage since (N7-P2 … N8-03D2) has run with it red. N8-03D2 added one more difference (`modelSchemaVersion`). It did not cause the failure.

**Is the contract changed?**
- **API shape: additive only.** No member was removed or renamed; 52 were added. The Android DTOs are declared tolerant: `AnalyzerDtos.kt:18` `ignoreUnknownKeys = true, coerceInputValues = true, explicitNulls = false`; "Every field has a default so that a member the service adds later … never turns a readable answer into a crash." (CV)
- **Values: changed.** The Kotlin `RealServerContractTest` parses the *committed* files, so it still tests the old answer. The phone has not been tested against today's answer: the new `preview.*` members and today's scene for this job.
- **Geometry:** the synthetic job builds a different (larger) model today. That is a solver change, not a contract change.

**Verdict:** the contract evidence is stale by 14 solver versions. Nothing found shows a breaking change, and the fixture was not refreshed (refreshing it to get a green test is exactly what the brief forbids).
- The test does its job: it says the phone was not tested against this server.
- The fix is a deliberate contract stage: capture, review the additive members against the DTOs, run the Kotlin tests. It is not a silent refresh.

## 5. VIEWER_RUNTIME — risk: LOW

- **Web BuildWorld:** loads models through `loadModel` (migrating) and compiles with the same `compileBuilding`.
  - In N8-03D2 the 1.6.0 BEFORE models and the 1.7.0 AFTER models of Arganiach and Trytomach rendered in one rebuilt viewer: 18/18 shots non-blank (RO, N8-03D2 review-shots logs).
  - A viewer bundle built before 1.7.0 cannot load 1.7.0 models (observed; see §1).
- **Android:** consumes compiled bundles only (§3). It is not exposed to the model schema at runtime.
